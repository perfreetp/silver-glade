# 机柜热力分析 · Rack Thermal Analyzer

面向高密度算力机房的机柜热力分析渲染工具。在浏览器内运行，全部数据留在本地，
结果打包导出带走。

- **技术栈**：TypeScript · Vue 3 · Babylon.js 9（WebGPU）· WGSL 计算着色器 · Vite
- **规模**：单机房 ≤ 200 个机柜，每个机柜前后各 ≤ 36 个温度采样点（6×6 栅格）
- **硬性指标**：等值面顶点 ≤ 30 万；连续拖动阈值 ≥ 30fps（实测 60fps）
- **隐私**：数据只在 IndexedDB / localStorage 与本机内存中，不发送任何网络请求

## 快速开始

```bash
npm install
npm run dev        # 开发服务器，默认 http://127.0.0.1:5173/
npm run build      # 类型检查 + 生产构建
npm run preview    # 预览生产构建
npm test           # 单元测试（vitest）
npm run test:e2e   # 端到端测试（需先 build + preview）
```

> **浏览器要求**：需要支持 WebGPU 的浏览器（Chrome / Edge 113+，Safari 18+）。
> 应用启动时会检测 `navigator.gpu`，不支持时给出明确提示而不是白屏。

## 四个模块

### ① 温度采样导入

自动识别三种格式，字段名不区分大小写、空格与下划线，支持中文表头。

**长表 CSV**（每行一个采样点）——最通用：

```csv
rack_id,row,col,facing,face,x,y,temp
R01,0,0,+Z,intake,0,0,23.4
R01,0,0,+Z,exhaust,0,0,35.1
```

**宽表 CSV**（每行一个机柜的一个面，共 36 列读数）：

```csv
rack_id,row,col,facing,face,v0,v1,…,v35
R01,0,0,+Z,intake,23.4,23.9,…
```

**JSON**（数组，或 `{ "racks": [...] }`，温度可以是嵌套 6×6 或扁平 36 元数组）：

```json
[{ "rack_id": "R01", "row": 0, "col": 0, "facing": "+Z",
   "intake":  [[23.4, …], …],
   "exhaust": [[35.1, …], …] }]
```

字段说明：

| 字段 | 别名示例 | 取值 |
| --- | --- | --- |
| `rack_id` | `rack`、`机柜`、`编号` | 任意唯一字符串 |
| `row` / `col` | `行` / `列` | 非负整数 |
| `facing` | `朝向`、`direction` | `+X` `-X` `+Z` `-Z`，或 东/西/南/北 |
| `face` | `风面`、`side` | `intake` / `exhaust`，或 进风/出风 |
| `x` / `y` | `横向` / `纵向` | 0..5，对应 6×6 栅格的列/行 |
| `temp` | `温度`、`temperature` | ℃；留空、`-`、`NA` 表示缺失 |

缺失的采样点会用该机柜同一面的均值插值补全，并在界面上给出警告；
机柜数超过 200、坐标越界、行列冲突等都会明确提示。

### ② 等值面视图

- 温度场以 WGSL 计算着色器铺成三维标量场，再用**移动立方体**在 GPU 上提取等值面，
  全过程不经过 CPU。
- 阈值 **25–60℃ 连续可调**。拖动时**只重跑移动立方体**，温度场与所有 GPU 缓冲区
  保持不变（已用自动化测试验证底层 `GPUBuffer` 对象前后一致）。
- 顶点数上限 **30 万**，超出预算的单元格在 GPU 内原子地跳过，绝不留半个三角形。
- 包裹体以两趟（背面 → 正面）半透明绘制，与机柜本体共用同一深度缓冲，遮挡关系正确。

### ③ 热力面板

- 进风面与出风面分别按**分段查找表**贴温度色带（三套色带：热力 / 炽焰 / 类地）。
- 选中机柜即显示该柜前后两面的 6×6 逐点温度、均值、极值与 ΔT。
- 等值面包裹体叠加在风面之上，深度排序正确。

### ④ 导出

一键打包为 `.zip`：

| 文件 | 内容 |
| --- | --- |
| `isosurface.obj` | 等值面网格，顶点第 4 分量是温度，可直接拖进 Blender |
| `isosurface.ply` | 二进制 PLY，含 `temperature` 属性，兼容 MeshLab / CloudCompare |
| `field.bin` | 三维温度场 Float32 原始数据（X 快变） |
| `field.json` | 标量场的维度、原点、体素尺寸与索引顺序 |
| `racks.json` | 机柜几何、朝向与两面 6×6 采样温度 |
| `manifest.json` | 阈值、调色板、坐标系、文件清单与生成时间 |
| `preview.png` | 当前视角截图（可选） |

## 性能设计

| 措施 | 效果 |
| --- | --- |
| 温度场与等值面都在 GPU 上计算 | 拖动阈值时 CPU 无计算 |
| 空间加速格剔除无关机柜 | 200 柜时每体素只检查附近的几台机柜 |
| 缓冲区按上限一次分配、全程复用 | 拖动阈值零分配、零 GC |
| 顶点绘制范围按 GPU 回读动态收缩 | 顶点少时不多画 |
| 体素尺寸自适应（≤ 82 万体素） | 机房越大格子越粗，帧率恒定 |

实测（Chrome 157，NVIDIA Pascal）：

- 24 柜：10 万级顶点，拖动阈值 **60fps**
- 200 柜：72.6 万体素，任何阈值 **60fps**，顶点数严格 ≤ 30 万

## 项目结构

```
src/
  model/        领域模型与机房几何布局
  io/           采样解析、示例数据、zip 导出
  engine/       WebGPU 管线、体素网格、色带、移动立方体表
  shaders/      全部 WGSL 着色器
  components/   Vue 面板（导入 / 等值面 / 热力 / 导出）与 3D 视口
  state/        响应式状态与本地持久化（IndexedDB + localStorage）
tests/
  unit/         解析、几何、导出格式的单元测试
  e2e/          真实 Chrome + WebGPU 的端到端与压力测试
tools/
  genMCTables.mjs   移动立方体表生成脚本（表为公开领域数据）
```

## 坐标系约定

右手系，+Y 向上，单位米。`facing` 表示**进风面法线**指向的方向；
出风面位于机柜背面。采样栅格的 `y=0` 为顶行，`x=0` 为从外侧看机柜的左侧。
